## 安装依赖包

选择你习惯的包管理器来安装 Nuxt Content v3：

::code-group
```bash [pnpm]
pnpm add @nuxt/content
```

```bash [yarn]
yarn add @nuxt/content
```

```bash [npm]
npm install @nuxt/content
```

```bash [bun]
bun add @nuxt/content
```
::

## 注册模块

在 `nuxt.config.ts` 中添加 Nuxt Content 模块：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/content']
})
```

## 自动安装

使用 `create-nuxt` CLI 创建新的 Nuxt 项目时，你只需在交互式模块选择器中选中 `@nuxt/content`，它就会自动为你安装并注册该模块。

::code-group
```bash [npm]
npm create nuxt <project-name>
```

```bash [yarn]
yarn create nuxt <project-name>
```

```bash [pnpm]
pnpm create nuxt <project-name>
```

```bash [bun]
bun create nuxt <project-name>
```

```bash [deno]
deno -A npm:create-nuxt@latest <project-name>
```
::

::note{color="warning"}
在 Node.js 中运行项目时，Nuxt Content 会询问你要使用哪个数据库连接器。
你可以选择安装 `better-sqlite3` 或 `sqlite3` 包。

:br

如果你不想安装任何包，可以使用 Node.js\@v22.5.0 或更高版本内置的原生 SQLite。
请查看 [`experimental.sqliteConnector`](/docs/getting-started/configuration#experimentalsqliteconnector) [配置](/docs/getting-started/configuration#experimentalsqliteconnector)。
::

::note{color="warning"}
如果你使用 **pnpm v10+**，依赖的构建脚本默认不会执行。

:br

由于 `better-sqlite3` 和 `sqlite3` 依赖 postinstall/build 步骤来生成原生绑定，
你可能会遇到如下错误：

:br

`Could not locate the bindings file`

:br

要解决这个问题，你可以通过运行以下命令来批准所需的构建脚本：

  :::code-group
  ```bash [pnpm]
  pnpm approve-builds
  ```
  :::

另外，如果你需要非交互式的方式（例如在 CI 中），
可以在项目根目录的 `package.json` 中添加以下配置，
以显式允许原生构建：

```json [package.json]
{
  "pnpm": {
    "onlyBuiltDependencies": [
      "better-sqlite3",
      "sqlite3"
    ]
  }
}
```

如果初次安装没有完成构建，
你可能还需要清除 `node_modules` 或显式执行一次构建：

  :::code-group
  ```bash [pnpm]
  pnpm rebuild better-sqlite3 sqlite3
  ```
  :::
::

## 创建你的第一个集合

在项目根目录创建 `content.config.ts` 文件：

```ts [content.config.ts]
import { defineContentConfig, defineCollection } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    content: defineCollection({
      type: 'page',
      source: '**/*.md'
    })
  }
})
```

该配置会创建一个默认的 `content` 集合，用于处理项目 `content` 文件夹中的所有 Markdown 文件。你可以根据需求自定义集合的设置。

::tip
`type: page` 表示内容文件与站点页面之间是一一对应的关系。
::

::note{to="/docs/collections/define"}
详见我们的 **集合指南**。
::

## 创建你的第一个 Markdown 页面

在项目根目录创建 `content/index.md` 文件：

```md [content/index.md]
# My First Page

Here is some content.
```

详细了解如何编写 [Markdown 页面](/docs/files/markdown)。

## 展示你的页面

创建 `pages/index.vue` 文件并展示页面内容：

```vue [pages/index.vue]
<script setup lang="ts">
const { data: home } = await useAsyncData(() => queryCollection('content').path('/').first())

useSeoMeta({
  title: home.value?.title,
  description: home.value?.description
})
</script>

<template>
  <ContentRenderer v-if="home" :value="home" />
  <div v-else>Home not found</div>
</template>
```

::note{icon="i-lucide-info"}
如果你是在一个全新的 Nuxt 项目中安装 Nuxt Content，并且项目还没有 `pages` 目录，那么你还需要修改 `app.vue` 文件，添加 `NuxtPage` 组件以便渲染页面。（如果你的项目中已经有页面，那就无需额外操作。）

```vue [app.vue]
<template>
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</template>
```
::

::tip{icon="i-lucide-rocket"}
大功告成！你已创建了第一个 Nuxt Content 页面。
::
