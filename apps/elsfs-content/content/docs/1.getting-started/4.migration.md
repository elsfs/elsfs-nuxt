---
title: 迁移
description: 如何从 v2 迁移到 v3
---

Nuxt Content v3 是从零重新构建的，由此诞生了一个能力更强的全新库。尽管我们在重新设计概念和组件时尽量与 Content v2 保持相似，但破坏性变更仍在所难免。

别担心，你无需修改内容文件。我们已确保 Content v3 以与 Content v2 相同的方式处理内容。

## 变更

### Vue 工具函数

- `queryContent()` API 已被新的 `queryCollection()` 取代

::prose-tip
新 API 由 SQL 支撑，内容查询在特定的集合内进行。
::

- `fetchContentNavigation()` API 已被新的 `queryCollectionNavigation()` 取代
- 相邻内容（Surroundings）现在有了独立的 API `queryCollectionItemSurroundings()`
- 文档驱动模式已被移除：`Markdown` 文件不会再自动转换为 Nuxt 页面，你需要自行创建页面，[查看这一节了解具体做法](/docs/components/content-renderer#example-usage)。
- `useContent()` 组合式函数已被移除
- `searchContent()` 已被移除，改用新的 `queryCollectionSearchSections` API
- 使用 `queryCollectionSearchSections` API 即可轻松实现全文搜索，[查看这一节了解具体做法](/docs/advanced/fulltext-search)

### 组件

- 所有内容都应使用 `<ContentRenderer>` 组件渲染。`<ContentDoc>`、`<ContentList>`、`<ContentNavigation>` 和 `<ContentQuery>` 组件已在 v3 中移除。
- v3 不再支持 `<ContentSlot>` 和 `<MDCSlot>` 组件。组件可以直接改用 Vue 原生的 `<slot>` 组件

::prose-note
`<ContentSlot>` 和 `<MDCSlot>` 最初的作用是在渲染前处理内容，并移除插槽内容外层的段落。这种解包行为现在通过 `<slot>` 组件上的 `mdc-unwrap` 属性支持。例如：`<slot mdc-unwrap="p" />`
::

- 在 `components/content` 目录下创建的组件不再自动注册为全局组件。如果你使用[动态渲染](https://vuejs.org/guide/essentials/component-basics.html#dynamic-components)在 markdown 文件之外渲染这些组件，就必须在 Nuxt 应用中手动注册它们。具体做法请参阅 [Nuxt - 自定义组件目录](https://nuxt.com/docs/guide/directory-structure/components#custom-directories)文档。

### 类型

- `import type { NavItem } from '@nuxt/content/dist/runtime/types'` 已被 `import type { ContentNavigationItem } from '@nuxt/content'` 取代

### 通用

- `_dir.yml` 文件已重命名为 `.navigation.yml`
- 模块选项中不再有 source 选项，你可以在 `content.config.ts` 中为集合定义[多个数据源](/docs/collections/sources)。
- 文档的 `._path` 现在重命名为 `.path`，同样，所有带 `_` 前缀的内部字段都已被移除或重命名。
- `useContentHelpers()` 已被移除
- 模块默认不会忽略点文件，你可以在集合源的 `exclude` 选项中添加 `ignore: ['**/.*']` 来忽略它们。
- 受 SQL 限制，排序现在使用字母顺序而非数字顺序。更多信息请查看[文件排序](/docs/collections/types#ordering-files)一节。
- 模块选项相比 v2 有所变化。详情请查看[配置页面](/docs/getting-started/configuration)。

## 在 v3 中实现文档驱动模式

在 Content v3 中实现文档驱动模式非常简单。你只需在 Nuxt 中创建一个全捕获（catch-all）页面，并根据路由路径获取内容。

```vue [pages/[...slug\\].vue]
<script lang="ts" setup>
const route = useRoute()
const { data: page } = await useAsyncData(route.path, () => {
  return queryCollection('content').path(route.path).first()
})
</script>

<template>
  <div>
    <header><!-- ... --></header>

    <ContentRenderer v-if="page" :value="page" />

    <footer><!-- ... --></footer>
  </div>
</template>
```

## 将 `queryContent` 转换为 `queryCollections`

如前所述，`queryContent` 已被移除，改用基于集合的新 API `queryCollection`。两者主要有两点区别：

1. `queryCollection` 构建的是面向 SQL 数据库的查询。
2. `queryCollection` 只在指定的集合内检索。你需要知道集合的名称（配置中的键名）。

```ts [按路径查找内容]
// Content v2
const v2Query = await queryContent(route.path).findOne()
// Content v3 - don't forget to create `content` collection in `content.config.ts`
const v3Query = await queryCollection('content').path(route.path).first()
```

```ts [使用自定义筛选查找内容]
// Content v2
const v2Query = await queryContent()
  .where({ path: /^\/hello\/.*/ })
  .find()
// Content v3 - don't forget to create `content` collection in `content.config.ts`
const v3Query = await queryCollection('content')
  .where('path', 'LIKE', '/hello%')
  .first()
```

## 转换 `queryContent().findSurround()`

Surround 现在有了独立的 API。

```ts
const targetPath = '/docs'

// Content v2
const v2Surround = await queryContent(targetPath)
  .only(['title', 'description', 'navigation'])
  .findSurround(withoutTrailingSlash(route.path))

// Content v3 - don't forget to create `content` collection in `content.config.ts`
const v3Surround = await queryCollectionItemSurroundings(
  'content',
  targetPath,
  {
    fields: ['title', 'description', 'navigation']
  }
)
```

## 合并 `ProsePre`、`ProseCode` 和 `ProseCodeInline` 组件

许多 `ProsePre` 组件只是对 `ProseCode` 组件的轻量封装。我们已将这三个组件合并为两个组件。现在 `ProsePre` 与多行代码块之间不再有区别。

1. MDC 现在会将单个反引号 `` ` `` 映射并解析为 `ProseCode`，而不再是 `ProseCodeInline`。
2. MDC 现在会将以三个反引号` ``` `开头的代码块映射并解析为 `ProsePre` 组件。

**建议的改动：**

1. 你现有的 `ProseCode` 逻辑应迁移到 `ProsePre`
2. 将你的 `ProseCodeInline` 组件重命名为 `ProseCode`

## `_dir.yml` 文件已重命名为 `.navigation.yml`

在 Content v3 中，我们将 `_dir.yml` 重命名为 `.navigation.yml`。新名称更能体现这些文件的用途。  
模块使用这些文件收集目录信息，用于生成导航。

请注意，要让模块能够读取这些文件，你需要以包含它们的方式定义集合的源。
例如 `source: '**'` 和 `source: '**/*.{md,yml}'` 会将这些文件纳入集合，
而 `source: '**/*.md'` 则不会。

## 忽略点文件

默认情况下，Content v3 不会忽略点文件。如果你想忽略它们，可以在集合源的 `exclude` 选项中添加 `ignore: ['**/.*']`。

```ts
defineCollection({
  source: {
    include: '**',
    exclude: ['**/.*']
  }
})
```

请注意，上面的模式也会把 `.navigation.yml` 文件排除在集合之外。如果你使用了 `.navigation.yml` 并希望保留它们，
可以使用 `**/.(!(navigation.yml))` 模式来排除除 `.navigation.yml` 之外的所有点文件。

```ts
defineCollection({
  source: {
    include: '**',
    exclude: ['**/.!(navigation.yml)']
  }
})
```
