---
title: 配置
description: Nuxt Content 已内置合理的默认配置。
---

要配置 content 模块并自定义其行为，可以在 `nuxt.config` 中使用 `content` 属性：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    // Options
  }
})
```

::note{to="https://github.com/nuxt-modules/mdc#configurations"}
除了通过 `content.markdown` 进行配置外，你还可以使用 `mdc` 属性，借助 Markdown Components（MDC）自定义 Markdown 元素的渲染方式。
::

## `build`

Nuxt Content 会在构建时读取并解析所有可用内容。该选项让你可以控制内容的解析行为。

### `markdown`

配置 markdown 解析器。

#### `toc`

::code-group
```ts [默认值]
toc: {
  depth: 2,
  searchDepth: 2
}
```

```ts [类型签名]
type Toc = {
  depth: number
  searchDepth: number
}
```
::

控制目录（Table of Contents）的生成行为。

取值：

- `depth`：包含在目录中的最大标题层级。
- `searchDepth`：查找标题时搜索的最大嵌套标签深度。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    build: {
      markdown: {
        toc: {
          depth: 3, // include h3 headings
        }
      }
    }
  }
})
```

#### `remarkPlugins`

::code-group
```ts [默认值]
remarkPlugins: {}
```

```ts [类型签名]
type RemarkPlugins = Record<string, false | MarkdownPlugin>
```
::

要使用的 [remark](https://github.com/remarkjs/remark) 插件列表。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    build: {
      markdown: {
        // Object syntax can be used to override default options
        remarkPlugins: {
          // Override remark-emoji options
          'remark-emoji': {
            options: {
              emoticon: true
            }
          },
          // Disable remark-gfm
          'remark-gfm': false,
          // Add remark-oembed
          'remark-oembed': {
            // Options
          }
        },
      }
    }
  }
})
```

#### `rehypePlugins`

::code-group
```ts [默认值]
rehypePlugins: {}
```

```ts [类型签名]
type RehypePlugins = object
```
::

要使用的 [rehype](https://github.com/remarkjs/remark-rehype) 插件列表。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    build: {
      markdown: {
        // Object syntax can be used to override default options
        rehypePlugins: {
          'rehype-figure': {

          }
        },
      }
    }
  }
})
```

#### `contentHeading`

::code-group
```ts [默认值]
contentHeading: true
```

```ts [类型签名]
type ContentHeading = boolean
```
::

将该选项设为 `false` 会禁用 `title` 和 `description` 字段的自动生成，这两个字段通常从第一个 H1 标题及其后续段落中提取。

#### `highlight`

::code-group
```ts [默认值]
highlight: false
```

```ts [类型签名]
type Highlight = false | object
```
::

Nuxt Content 使用 [Shiki](https://github.com/shikijs/shiki) 为 [`ProsePre`](/docs/components/prose#prosepre) 和 [`ProseCode`](/docs/components/prose#prosecode) 提供语法高亮。

| 选项 | 类型 | 说明 |
| - | - | - |
| `theme` | `ShikiTheme` 或 `Record<string, ShikiTheme>` | 要使用的[颜色主题](https://github.com/shikijs/shiki/blob/main/docs/themes.md)。 |
| `langs` | `ShikiLang[]` | 可用于高亮的[已加载语言](https://github.com/shikijs/shiki/blob/main/docs/languages.md)。 |

- `highlight.theme`

主题既可以用单个字符串指定，也支持使用包含多个主题的对象。

该选项与 [Color Mode 模块](https://color-mode.nuxtjs.org/)兼容。

如果你使用多个主题，建议始终指定一个 `default` 主题。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    build: {
      markdown: {
        highlight: {
          // Theme used in all color schemes.
          theme: 'github-light',
          // OR
          theme: {
            // Default theme (same as single string)
            default: 'github-light',
            // Theme used if `html.dark`
            dark: 'github-dark',
            // Theme used if `html.sepia`
            sepia: 'monokai'
          }
        }
      }
    }
  }
})
```

- `highlight.langs`

默认情况下，模块会加载若干语言用于语法高亮：

```ts [默认值]
['json', 'js', 'ts', 'html', 'css', 'vue', 'shell', 'mdc', 'md', 'yaml']
```

如果你打算使用其他语言的代码示例，就需要在该选项中声明这些语言。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    build: {
      markdown: {
        highlight: {
          langs: [
            'c',
            'cpp',
            'java'
          ]
        }
      }
    }
  }
})
```

如果你想为某个尚未支持的语言添加高亮，可以通过加载该语言的语法文件来实现。

```ts [nuxt.config.ts]
import { readFileSync } from 'node:fs'

export default defineNuxtConfig({
  content: {
    build: {
      markdown: {
        highlight: {
          langs: [
            // Read more about Shiki languages: https://shiki.style/guide/load-lang
            JSON.parse(
              readFileSync('./shiki/languages/gdscript.tmLanguage.json', 'utf-8'),
            ),
          ]
        }
      }
    }
  }
})
```

在 [Shiki 文档](https://github.com/shikijs/shiki/blob/main/docs/languages.md#adding-grammar)中了解更多关于添加语言的内容。

### `pathMeta`

content 模块会使用文件路径来生成 slug、默认标题和内容顺序，你可以通过 `pathMeta` 选项自定义这一行为。

#### `pathMeta.forceLeadingSlash`

如果设为 `true`，路径会以斜杠开头。默认值为 `true`。

#### `pathMeta.slugifyOptions`

content 模块使用 [slugify](https://github.com/simov/slugify) 生成 slug，你可以通过该选项自定义 slugify 的行为。

请查看 [slugify 选项](https://github.com/simov/slugify#options)了解更多信息。

### `transformers`

Nuxt Content 为每种内容类型都提供了专用的转换器，用于解析原始内容并为其查询和渲染做好准备。通过该选项，你可以定义自定义转换器，以支持新的内容类型，或增强现有内容类型的功能。

::code-group
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    build: {
      transformers: [
        '~/transformers/title-suffix',
      ],
    },
  },
})
```

```ts [~/transformers/title-suffix.ts]
import { defineTransformer } from '@nuxt/content'

export default defineTransformer({
  name: 'title-suffix',
  extensions: ['.md'],
  transform(file) {
    return {
      ...file,
      title: file.title + ' (suffix)',
    }
  },
})
```

::

在[转换器](/docs/advanced/transformers)文档中了解更多关于转换器的内容。

## `database`

默认情况下，Nuxt Content 使用本地 SQLite 数据库来存储和查询内容。如果你想使用其他数据库，或者计划部署到 Cloudflare Workers，可以修改该选项。

以下是受支持的数据库适配器列表：

### `SQLite`

如果你想更改默认的数据库位置并将其迁移到别处，可以使用 `sqlite` 适配器。这也是 `database` 选项的默认值。根据你的运行时环境，会使用不同的 sqlite 适配器（Node：better-sqlite-3，Bun：bun\:sqlite）。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    database: {
      type: 'sqlite',
      filename: 'SQLITE_DB_LOCATION'
    }
  }
})
```

如果你无法使用常规的基于文件的 SQLite 数据库（例如因为只读文件系统或平台限制），可以让 SQLite 完全运行在内存中。Nuxt Content 会在首次查询时从生成的转储文件恢复数据库。在无服务器平台上，该数据库会在每次冷启动时重新创建；请尽可能预渲染更多路由，以避免运行时反复初始化。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    database: {
      type: 'sqlite',
      filename: ':memory:'
    }
  }
})
```

### `D1`

如果你计划将应用部署到 Cloudflare Workers，就需要使用 `d1` 数据库适配器。请在 Cloudflare 控制台中创建一个 `d1` 绑定，并填写 `bindingName` 字段。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    database: {
      type: 'd1',
      bindingName: 'CF_BINDING_NAME'
    }
  }
})
```

### `Postgres`

如果你计划使用 PostgreSQL 数据库部署应用，就需要使用 `postgresql` 数据库适配器。

首先，请确保安装 `pg` 包：

```bash [终端]
npm i pg
```

然后，在 `nuxt.config.ts` 中配置 `postgresql` 适配器：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    database: {
      type: 'postgresql',
      url: process.env.POSTGRES_URL,
      /* Other options for `pg` */
    }
  }
})
```

### `LibSQL`

如果你计划使用 LibSQL 数据库部署应用，就需要使用 `libsql` 数据库适配器。

首先，请确保安装 `@libsql/client` 包：

```bash [终端]
npm i @libsql/client
```

然后，在 `nuxt.config.ts` 中配置 `libsql` 适配器：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    database: {
      type: 'libsql',
      url: process.env.TURSO_DATABASE_URL,
      authToken: process.env.TURSO_AUTH_TOKEN,
    }
  }
})
```

::note
最受欢迎的 LibSQL 托管服务是 [Turso](https://turso.tech/)。
::

### `PGlite`

如果你计划使用 PGlite 数据库部署应用，就需要使用 `pglite` 数据库适配器。

首先，请确保安装 `@electric-sql/pglite` 包：

```bash [终端]
npm i @electric-sql/pglite
```

然后，在 `nuxt.config.ts` 中配置 `pglite` 适配器：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    database: {
      type: 'pglite',
      dataDir: '.data/content/pglite'
    }
  }
})
```

::note
我们建议只在开发环境中使用 PGlite。
::

## `renderer`

配置内容渲染器。

### `anchorLinks`

::code-group
```ts [默认值]
{ h2: true, h3: true, h4: true }
```

```ts [类型签名]
type AnchorLinks = boolean | Record<'h1' | 'h2' | 'h3' | 'h4' | 'h5' | 'h6', boolean>
```
::

控制锚点链接的生成。默认会为 `h2`、`h3` 和 `h4` 标题生成锚点链接

取值：

- `false`：禁用链接生成。
- `true`：为所有标题启用链接生成。

### `alias`

::code-group
```ts [默认值]
alias: {}
```

```ts [类型签名]
type Alias = Record<string, string>
```
::

别名用于替换 markdown 组件，以渲染自定义组件而非默认组件。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    renderer: {
      alias: {
        p: 'MyCustomParagraph'
      }
    }
  }
})
```

## `watch`

```ts [默认值]
watch: {
  enabled: true
}
```

控制开发期间是否启用内容热重载。

**选项：**

- `enabled`（`boolean`）：在编辑内容文件时启用或禁用热重载。  
  - `true`（默认）：开发期间自动重新加载应用中的内容变更。
  - `false`：禁用热重载；内容变更后需要手动刷新。

::callout
内容监听器只在开发环境运行，它借助 Vite 开发服务器检测内容更新，并向你的应用发送事件以实现实时更新。
::

## `llms`

```ts [默认值]
llms: true
```

控制 [`nuxt-llms` 集成](/docs/integrations/llms)。安装 `nuxt-llms` 后，Nuxt Content 会将你的页面集合注入 `llms.txt`，并在 `/raw/` 下暴露原始 markdown 端点。

将其设为 `false` 即可退出，例如当其他模块已经提供原始 markdown 路由时：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    llms: false,
  },
});
```

## `experimental`

尚未稳定的实验性特性。

### `experimental.sqliteConnector`

SQLite 连接器在不同环境中各有局限：有些能在无服务器环境中工作，有些则不能。Nuxt Content 支持四种不同的 SQLite 连接器，以覆盖所有环境：

- `better-sqlite3`：适用于所有 Node 环境、GitHub CI、Vercel CI 与生产环境、Cloudflare CI 流水线等。（在 WebContainers、StackBlitz 或 Bun 运行时中**不可**用）
- `sqlite3`：适用于 Node 环境、GitHub CI 和 StackBlitz。（在 Vercel 或 Cloudflare 中**不可**用）
- `native`：从 Node.js v22.5.0 起，Node.js 原生提供 `node:sqlite` 模块。该连接器适用于 Node.js 版本为 22.5.0 或更高的所有 Node 环境。
- `bun`：使用 Bun 内置的 `bun:sqlite` 模块。部署到 Bun 运行时（例如使用 `bun1.x` 运行时的 Vercel）时必须使用。使用 Bun 构建时会自动选用，但若用 Node.js 构建、以 Bun 运行时为目标，则必须显式设置。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    experimental: { sqliteConnector: 'native' },
  },
});
```

部署到使用 Bun 运行时的 Vercel 时，如果你通过 Nitro 配置该运行时，连接器会被自动检测：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    vercel: {
      functions: {
        runtime: 'bun1.x',
      },
    },
  },
});
```

你也可以显式设置连接器：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    experimental: { sqliteConnector: 'bun' },
  },
});
```

::prose-note
当设置了 `sqliteConnector: 'bun'`，但构建运行在 Node.js 上（在 Vercel 等 CI/CD 流水线中很常见）时，构建时的内容处理会自动回退到兼容 Node.js 的连接器（例如 `better-sqlite3`）。只有部署后的服务端运行时才会使用 `bun:sqlite`。无需额外配置。
::

### `experimental.nativeSqlite`（已废弃，请使用 `sqliteConnector`）

从 Node.js v22.5.0 起，Node.js 原生提供 `node:sqlite` 模块。
这让 Nuxt Content 无需外部包即可将 SQLite 用作数据库。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    experimental: { nativeSqlite: true },
  },
});
```

::prose-note
该特性仅在 Node.js v22.5.0 及以上版本可用。在更早的版本中启用不会有任何效果。
::
