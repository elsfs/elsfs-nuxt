## 什么是无服务器托管？

无服务器托管让你无需直接管理服务器就能运行代码和应用——你只需上传代码，云服务商就会自动处理所有基础设施、扩缩容和运维工作，而你只需为实际消耗的计算资源付费。

**在无服务器环境中，每个用户请求都会触发一个全新的 Nuxt 服务器实例，也就是说每次都从零启动。**这种「无状态」特性意味着你无法把数据存储在服务器内存中，也不能使用 SQLite 这样基于文件的数据库。因此我们需要使用外部数据库服务（例如 D1、Turso 或 PostgreSQL），让数据独立于服务器实例持久保存。

## 使用无服务器平台部署

该模块内置了对多个知名无服务器平台的支持，你可以轻松把项目部署到这些平台。请查看各个平台的指南：

- [Cloudflare Pages](/docs/deploy/cloudflare-pages)
- [Vercel](/docs/deploy/vercel)

如果你想部署到其他平台，可以按照下面的步骤操作。

### 1. 选择数据库服务

在部署项目之前，你需要选择一种数据库服务：

::code-group
```ts [PostgreSQL]
// 1. Create a PostgreSQL database
// 2. And add the `POSTGRES_URL` to the env variables
export default defineNuxtConfig({
  content: {
    database: {
      type: 'postgresql',
      url: process.env.POSTGRES_URL
    }
  }
})
```

```ts [Cloudflare D1]
// 1. Create a D1 database in your CF account
// 2. Link it to your project with the same binding name
export default defineNuxtConfig({
  content: {
    database: {
      type: 'd1',
      bindingName: '<YOUR_BINDING_NAME>'
    }
  }
})
```

```ts [LibSQL]
// 1. Create a LibSQL database on Turso.tech
// 2. And add the `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` env variables
export default defineNuxtConfig({
  modules: ['@nuxt/content'],
  content: {
    database: {
      type: 'libsql',
      url: process.env.TURSO_DATABASE_URL,
      authToken: process.env.TURSO_AUTH_TOKEN,
    }
  }
})
```
::

### 2. 部署你的项目

Nuxt Content 使用 Nuxt 的部署预设，来针对不同的托管平台调整构建流程。

多种无服务器平台都支持零配置部署：

- [Cloudflare](https://nuxt.com/deploy/cloudflare)
- [NuxtHub](https://nuxt.com/deploy/nuxthub)
- [Vercel](https://nuxt.com/deploy/vercel)
- [Netlify](https://nuxt.com/deploy/netlify)

你只需把构建命令设置为：

```bash [Terminal]
nuxi build
```

生成的产物将与所选的平台兼容。

::note
关联的数据库会在服务器启动时于服务端加载。在浏览器中，则会加载一个 [WASM SQLite](/docs/advanced/database#wasm-sqlite-in-browser) 数据库，用于客户端导航或操作。
::

::tip
如果你想部署到 AWS Lambda 或 Azure Static Web Apps，需要确保 SQLite 文件位于 `/tmp` 中，因为这是唯一可写的目录

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/content'],
  content: {
    database: {
      type: 'sqlite',
      filename: '/tmp/contents.sqlite'
    }
  }
})
```
::

### 3. 通过预渲染优化性能

由于每个请求都会触发一个全新的 Nuxt 服务器实例，如果不预渲染部分页面，你的无服务器应用性能就会受到影响。

要优化无服务器应用，你可以使用 `routeRules` 选项预渲染页面：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true }
  }
})
```

::tip{to="https://hub.nuxt.com/docs/recipes/pre-rendering"}
我们建议查看 **NuxtHub 的预渲染指南**，了解优化无服务器应用的不同策略，该指南适用于所有无服务器平台。
::
