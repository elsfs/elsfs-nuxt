在 Nuxt Content 中，你可以根据集合文件的用途为每个集合指定类型。集合可以定义为 **page** 或 **data** 类型。

无论哪种类型，都会生成内置字段。每个集合都包含以下默认字段：

- `id`：唯一的内容标识符
- `stem`：不含扩展名的文件路径（用于排序和定位）
- `extension`：文件扩展名
- `meta`：集合模式中未定义的自定义字段

## page 类型

```ts
defineCollection({
  source: '**/*.md',
  type: 'page'
})
```

::tip
如果内容文件与站点页面之间是一一对应的关系，请使用 **page** 类型。
::

### 路径生成

Nuxt Content 会为集合中的每个文件自动生成路径，便于创建 URL 映射。

以下是根据文件结构生成路径的示例：

| 文件                             | 路径                  |
| -------------------------------- | --------------------- |
| `content/index.md`               | `/`                   |
| `content/about.md`               | `/about`              |
| `content/blog/index.md`          | `/blog`               |
| `content/blog/hello.md`          | `/blog/hello`         |
| `content/1.guide/2.installation` | `/guide/installation` |

::note
你可以使用辅助函数 [`queryCollection('COLLECTION').path('PATH')`](/docs/utils/query-collection) 按指定路径获取内容。
::

### 模式覆盖

当你使用 **page** 类型时，Nuxt Content 会生成若干网页常用的标准字段。这些字段提供了结构，并会**自动**应用到集合的模式中：

- `path`：生成的路由路径
- `title`：页面标题
- `description`：页面描述
- `seo`：SEO 元数据（配合 Nuxt 的 `useSeoMeta` 组合式函数使用）
- `body`：以 AST 形式解析的页面内容
- `navigation`：页面导航配置（用于 [queryCollectionNavigation](/docs/utils/query-collection-navigation)）

对应的模式如下：

```ts
  path: z.string(),
  title: z.string(),
  description: z.string(),
  seo: z.intersection(
    z.object({
      title: z.string().optional(),
      description: z.string().optional(),
      meta: z.array(z.record(z.string(), z.any())).optional(),
      link: z.array(z.record(z.string(), z.any())).optional(),
    }),
    z.record(z.string(), z.any()),
  ).optional().default({}),
  body: z.object({
    type: z.string(),
    children: z.any(),
    toc: z.any(),
  }),
  navigation: z.union([
    z.boolean(),
    z.object({
      title: z.string(),
      description: z.string(),
      icon: z.string(),
    }),
  ]).default(true),
```

::note
你可以通过在集合模式中定义这些字段来覆盖它们。
::

`navigation` 对象也是供 [`queryCollectionNavigation`](/docs/utils/query-collection-navigation) 使用的自定义元数据的存放位置。在页面 frontmatter 或 `.navigation.yml` 中，`section`、`group`、`badge` 等字段应嵌套在 `navigation` 下，它们会暴露在生成的 `ContentNavigationItem` 上。

## data 类型

```ts
defineCollection({
  source: 'authors/**.yml',
  type: 'data'
})
```

data 类型适用于那些并不直接对应网页，而是代表你希望在应用中查询和展示的结构化数据。

使用 data 集合时，你可以完全掌控模式，自由定义自定义结构。

::note
集合类型与文件扩展名之间没有严格的对应关系。例如，**page** 集合可以使用 [Markdown](/docs/files/markdown)、[YAML](/docs/files/yaml) 或 [JSON](/docs/files/json) 文件，而 **data** 集合同样可以使用这些格式。
::

## 文件排序

无论哪种类型，你可能都希望控制内容在列表中的显示顺序。可以在文件和目录名中使用数字前缀来指定顺序。Nuxt Content 在排序内容列表时会使用这些数字。

::note
Nuxt Content 使用字母顺序排序，因此如果你想按数值顺序排列，需要为个位数加上 `0` 前缀。例如，不加 `0` 前缀时，`10.foo.md` 会排在 `2.bar.md` 之前。
::

```text [Directory structure]
content/
  1.frameworks/
    1.vue.md
    2.nuxt.md
    ...
  2.examples/
    01.nuxthub.md
    02.vercel.md
    03.netlify.md
    04.heroku.md
    ...
    10.cloudflare.md
    index.md
```

::warning
文件名与数字之间使用 `.` 字符分隔。使用其他分隔符将无法生效。
::
