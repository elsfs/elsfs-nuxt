Nuxt Content 提供了多种将内容文件导入集合的方式。你可以在 `defineCollection` 中通过 `source` 属性来配置来源：

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      source: '**',
      type: 'page'
    })
  }
})
```

## `source`

`source` 属性既可以定义为字符串（遵循 glob 模式），也可以定义为对象，从而为内容目录中的目标目录和文件提供更细致的来源配置。

**示例：**

- `source: '**'` 包含内容目录及其子目录中的所有文件。
- `source: '**/*.md'` 包含内容目录及其子目录中的所有 `Markdown` 文件。
- `source: 'docs/**/*.yml'` 包含 `content/docs` 及其子目录中的所有 `YML` 文件。
- `source: '**/*.{json,yml}'` 包含内容目录及其所有子目录中的 `JSON` 或 `YML` 文件。
- `source: '*.json'` 仅包含直接位于内容目录中的 `JSON` 文件，不包含任何子目录。

### `include`（必填）

目标仓库以及内容目录中文件的 glob 模式。

### `exclude`

用于将内容排除在导入之外的 glob 模式。

### `prefix`

该配置仅适用于内容文件与站点页面一一对应的 **page** 类型。

它表示该页面在网站上的路径前缀（基础 URL）。

::prose-warning
`prefix` 必须以 `/` 开头。
::

默认情况下，模块会提取 `source`（或 `source.include`）中的静态前缀，并将其用作内容路径的前缀。例如，如果你定义来源为 `/en/**`，模块会自动把 `prefix` 填为 `/en`。你也可以手动提供前缀来覆盖这一行为。在集合来源中设置 `prefix: '/'` 即可移除前缀。

```ts
defineCollection({
  type: "page",
  source: {
    include: "en/**",
    exclude: ["en/index.md"],
    prefix: '/'
  }
})
```

### `cwd`

用于内容匹配的根目录。

**示例：**

如果你想包含内容目录之外某个文件夹中的文件，请把该文件夹的绝对路径设置为 `cwd` 属性。

```ts
source: {
  cwd: path.resolve('packages/my-pkg/docs'),
  include: '**/*.md',
}
```

### `repository`

外部来源，表示远程 Git 仓库 URL（例如 <https://github.com/nuxt/content>），或一个包含 Git 分支/标签信息、或可选认证信息的对象。

定义外部来源时，还必须定义 `include` 选项。
`include` 模式对模块至关重要，它让模块知道该集合要使用哪些文件。

```js
import { defineCollection, defineContentConfig } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      type: 'page',
      source: {
        repository: 'https://github.com/nuxt/content',
        include: 'docs/content/**',
      },
    })
  }
})
```

#### `branch` / `tag`
该选项允许按标签或分支克隆 Git 仓库。

**示例：**
如果你想按标签克隆，请把 `repository` 属性写成一个对象，包含仓库的 `url`，并设置 `tag` 属性。

```js
import { defineCollection, defineContentConfig } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      type: 'page',
      source: {
        repository: {
          url: 'https://github.com/nuxt/content',
          tag: 'v1'
        },
        include: 'docs/content/**',
      },
    })
  }
})
```

**示例：**

如果你想按远程分支克隆，请把 `repository` 属性写成一个对象，包含仓库的 `url`，并设置 `branch` 属性。

```js
import { defineCollection, defineContentConfig } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      type: 'page',
      source: {
        repository: {
          url: 'https://github.com/nuxt/content',
          branch: 'dev'
        },
        include: 'docs/content/**',
      },
    })
  }
})
```

#### `auth`

该选项允许为 Git 仓库使用基础认证和基于令牌的认证。

::warning{icon="i-lucide-shield-alert"}
切勿在代码中直接提交认证令牌或凭据。请在运行时通过环境变量或其他安全方式提供这些值。
::

**示例：**

如果你想使用基础认证（例如 BitBucket 仓库），可以这样写：

```ts
defineCollection({
  type: 'page',
  source: {
    repository: {
      url: 'https://bitbucket.org/username/repo',
      auth: {
        username: 'username',
        password: 'password',
      },
    },
  },
})
```

**示例：**

如果你需要使用认证令牌（例如 GitHub、GitLab 或某些 Forgejo 服务商），可以这样写：

```ts
defineCollection({
  type: 'page',
  source: {
    repository: {
      url: 'https://github.com/username/repo',
      auth: {
        username: 'username',
        token: 'password',
      },
    },
  },
})
```
