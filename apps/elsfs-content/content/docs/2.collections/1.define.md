Nuxt Content 模块会自动解析位于 Nuxt 应用根目录下 `content/` 目录中的所有内容文件。这样的机制让你可以按项目需要自由组织目录结构。

为了更好地组织内容，可以考虑使用内容集合（Content Collections），它能让你更高效地对内容进行分类和管理。这些集合在 `content.config.ts` 文件中定义。

::warning
如果不存在 `content.config.ts` 文件，内容目录下的所有文件默认都会被解析并导入。但一旦添加了配置文件，就只有匹配集合中指定路径模式的文件才会被导入。
::

## 什么是内容集合？

内容集合用于组织 Nuxt Content 项目中的相关条目。它们提供了一种结构化的内容管理方式，让站点的数据更易于查询、展示和维护。

主要特性包括：

- **逻辑分组**：将相似的内容归到一起，例如博客文章、产品页面或文档文章
- **共享配置**：为集合内的所有条目应用通用的设置与校验
- **更高效的查询**：高效地获取和筛选相关内容条目
- **自动类型推断**：在开发环境中获得类型安全与自动补全
- **灵活的结构**：可以按内容类型、分类或任何符合你需求的逻辑方式来组织集合

## 定义集合

在项目根目录创建 `content.config.ts` 文件。这个特殊文件用于配置集合数据库、工具类型以及内容处理方式。

下面是一个基本示例：

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      // Specify the type of content in this collection
      type: 'page',
      // Load every file inside the `content` directory
      source: '**',
    })
  }
})
```

::warning
目前，一篇文档在设计上只能同时存在于一个集合中。如果一个文件被多个集合引用，热更新将无法正常工作。为避免这种情况，建议使用 `exclude` 属性，配合合适的正则模式，将该文档从其他集合中显式排除。

该问题仍在此 issue 中讨论：[nuxt/content#2966](https://github.com/nuxt/content/issues/2966)。
::

### 集合模式

模式用于约束集合内的数据一致性，同时也是 TypeScript 类型的唯一来源。

在内置字段之外，你还可以为集合添加 `schema` 属性，通过 [`zod`](https://zod.dev) 模式来定义自己的模式：

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@nuxt/content'
import { z } from 'zod'

export default defineContentConfig({
  collections: {
    blog: defineCollection({
      type: 'page',
      source: 'blog/*.md',
      // Define custom schema for docs collection
      schema: z.object({
        tags: z.array(z.string()),
        image: z.string(),
        date: z.date()
      })
    })
  }
})
```

::note
`@nuxt/content` 导出了一个 `z` 对象，其中包含一组用于常见数据类型的 Zod 模式。完整的 Zod 工作原理与可用特性说明请查阅 [Zod 的 README](https://github.com/colinhacks/zod)。
::

::tip
你可以按需定义任意数量的集合，用来组织不同类型的内容。
::

### 数据库索引

通过在集合列上定义索引来优化查询性能。对于用于筛选、排序或查找的字段，索引尤为有用。

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@nuxt/content'
import { z } from 'zod'

export default defineContentConfig({
  collections: {
    products: defineCollection({
      type: 'data',
      source: 'products/*.json',
      schema: z.object({
        sku: z.string(),
        price: z.number(),
        category: z.string(),
        inStock: z.boolean(),
      }),
      indexes: [
        // Single column indexes
        { columns: ['category'] },
        { columns: ['price'] },

        // Composite index for category + price filtering
        { columns: ['category', 'price'] },

        // Unique index to ensure SKU uniqueness
        { columns: ['sku'], unique: true },

        // Custom index name (optional)
        { columns: ['inStock', 'category'], name: 'idx_stock_category' },
      ],
    }),
  },
})
```

::note
索引会在生成数据库模式时自动创建。它们适用于所有受支持的数据库：SQLite、Cloudflare D1、PostgreSQL、LibSQL 和 PGlite。
::

::tip{icon="i-lucide-lightbulb"}
**Cloudflare D1 成本优化**：有了索引，当只有一条匹配记录时，在已建索引的列上执行 `WHERE` 条件只计为读取 1 行。没有索引时，D1 会统计表中被扫描的所有行，从而显著增加读取成本。索引可以大幅降低你的 D1 账单。
::

**索引配置选项：**

- **`columns`**（必填）：要包含在索引中的列名数组
- **`unique`**（可选）：设为 `true` 以创建唯一索引（默认：`false`）
- **`name`**（可选）：自定义索引名。若省略，会自动生成为 `idx_{collection}_{column1}_{column2}`

**性能建议：**

- 为 `where()` 查询中用到的列建立索引，以加快筛选
- 为 `sort()` 中用到的列建立索引，以优化排序
- 对需要按多个列筛选/排序的查询使用复合索引
- 唯一索引会自动施加数据唯一性约束

## 查询集合

使用 [`queryCollection`](/docs/utils/query-collection) 工具函数从集合中获取一条或全部条目：

```vue [pages/blog.vue]
<script setup lang="ts">
const { data: posts } = await useAsyncData('blog', () => queryCollection('blog').all())
</script>

<template>
  <div>
    <h1>Blog</h1>
    <ul>
      <li v-for="post in posts" :key="post.id">
        <NuxtLink :to="post.path">{{ post.title }}</NuxtLink>
      </li>
    </ul>
  </div>
</template>
```

::note{to="/docs/utils/query-collection"}
在我们的 `queryCollections` API 文档中了解可用的查询选项。
::

## defineCollection()

`defineCollection` 函数用于在内容配置中定义集合。它的 TypeScript 签名如下：

```ts
function defineCollection(collection: Collection): DefinedCollection

type Collection = {
  // Determines how content is processed
  type: 'page' | 'data'
  // Specifies content location
  source?: string | CollectionSource
  // Zod schema for content validation and typing
  schema?: ZodObject<T>
  // Database indexes for query optimization
  indexes?: CollectionIndex[]
}

type CollectionIndex = {
  // Column names to include in the index
  columns: string[]
  // Optional custom index name
  name?: string
  // Whether this is a unique index (default: false)
  unique?: boolean
}
```

::note{to="/docs/collections/types"}
了解有关集合类型的更多内容。
::

```ts
type CollectionSource = {
  // Glob pattern for content matching
  include: string
  // .path prefix (only applies to 'page' type)
  prefix?: string
  // Glob patterns to exclude content
  exclude?: string[]
  // Root directory for content matching
  cwd?: string
  // Remote git repository URL (e.g., https://github.com/nuxt/content)
  repository?: string
  // Authentication token for private repositories (e.g., GitHub personal access token)
  authToken?: string
}
```

::note{to="/docs/collections/sources"}
了解有关集合来源的更多内容。
::

该函数返回定义好的集合对象。
