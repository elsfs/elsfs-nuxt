Nuxt Content 支持用多种校验器定义集合模式。开箱即用的就包括 **Zod v3 / v4** 和 **Valibot** 等流行库（示例如下）。该系统可扩展，能通过 JSON Schema 适配器支持其他校验器。模式用于约束数据一致性，并驱动生成的类型与 Studio 表单。

## 使用 Zod v3

### 安装

```bash
pnpm add -D zod zod-to-json-schema
# or
npm i -D zod zod-to-json-schema
```

推荐直接从 `zod` 导入 `z`。

```ts [content.config.ts]
import { defineContentConfig, defineCollection, property } from '@nuxt/content'
import { z } from 'zod' // or 'zod/v3' if your setup exposes this subpath

export default defineContentConfig({
  collections: {
    blog: defineCollection({
      type: 'page',
      source: 'blog/*.md',
      schema: z.object({
        title: z.string(),
        description: z.string().optional(),
        date: z.date(),
        draft: z.boolean().default(false),
        tags: z.array(z.string()).optional(),
        image: z.object({
          src: property(z.string()).editor({ input: 'media' }),
          alt: z.string()
        })
      })
    })
  }
})
```

::note
日期在底层会被序列化为 ISO 字符串（JSON Schema 的 `format: date-time`）。
::

::warning
从 `@nuxt/content` 重新导出的 `z` 已废弃，并将在未来的版本中移除。请改为从 `zod`（或 `zod/v3`）导入 `z`。
::

## 使用 Zod v4

Zod v4 提供了原生的 JSON Schema 导出，不再需要 `zod-to-json-schema` 依赖。

### 安装 Zod

```bash
pnpm add -D zod
# or
npm i -D zod
```

```ts [content.config.ts]
import { defineContentConfig, defineCollection, property } from '@nuxt/content'
import { z } from 'zod/v4'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      type: 'page',
      source: 'docs/**/*.md',
      schema: z.object({
        title: z.string(),
        description: z.string().optional(),
        updatedAt: z.date(),
        draft: z.boolean().optional(),
        tags: z.array(z.string()).optional(),
        hero: z.object({
          image: property(z.string()).editor({ input: 'media' }),
          caption: z.string().optional()
        })
      })
    })
  }
})
```

## 使用 Valibot

使用 Valibot 的基础构造器来定义你的模式。
### 安装 Valibot

```bash
pnpm add -D valibot @valibot/to-json-schema
# or
npm i -D valibot @valibot/to-json-schema
```

```ts [content.config.ts]
import { defineContentConfig, defineCollection, property } from '@nuxt/content'
import { object, string, boolean, array, date, optional } from 'valibot'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      type: 'page',
      source: 'docs/**/*.md',
      schema: object({
        title: string(),
        description: optional(string()),
        updatedAt: date(),
        draft: optional(boolean()),
        tags: optional(array(string())),
        hero: object({
          image: property(string()).editor({ input: 'media' }),
          caption: optional(string())
        })
      })
    })
  }
})
```

## 选择校验器

- **Zod v3**：久经考验、生态丰富；配合重新导出的 `z` 有出色的开发体验。
- **Valibot**：轻量且快速；需要你自行从 `valibot` 导入。

只安装并使用你需要的校验器。Nuxt Content 会自动检测已安装且受支持的校验器。

## 支持其他校验器

Nuxt Content 会在内部把你的集合模式转换为 JSON Schema Draft-07。只要你偏好的校验器能够转换为 Draft-07（或存在兼容的适配器），它就能获得支持。目前会自动检测 Zod（v3 与 v4）和 Valibot。如果你希望某个校验器获得一等支持，欢迎在 [Nuxt Content 仓库](https://github.com/nuxt/content)中提交 issue 或 PR。

## 编辑器元数据（可选）

使用这两种校验器时，都可以通过 `property(...).editor({ ... })` 为 Studio 丰富字段信息。字段映射的细节请参阅 Studio 文档。

::tip{to="https://nuxt.studio/content#form-editor"}
了解编辑器元数据如何映射为 Studio 中的表单输入。
::
