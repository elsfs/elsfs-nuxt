# **Nuxt Content 3.0 正式发布**

我们非常高兴地宣布 Nuxt Content 3.0.0 首个稳定版发布 ✨

## 🚀 性能改进

Nuxt Content v3 从基于文件的存储方式转向 SQL 数据库系统。查询大型数据集时，用数据库替代文件存储可以减少大量 I/O 操作。

::prose-note
新的数据库系统改进了数据文件的存储与组织方式，带来更好的性能和可扩展性。这次更新完全发生在底层，不会影响你在 Content 中可用的文件类型（`yml`、`json` 和 `markdown`）。
::

这一切换对用户是透明的，Nuxt Content 依然为零配置支持开发模式、[服务端托管](/docs/deploy/server)和[静态生成](/docs/deploy/static)。

此外，现在还支持[无服务器](/docs/deploy/serverless)托管，客户端导航性能也得到了提升。

### 无服务器兼容性

Nuxt Content v2 的一个关键挑战是存储所有内容文件所需的打包体积过大。在部署到 [Netlify](https://netlify.com)、[NuxtHub](https://hub.nuxt.com) 或 [Vercel](https://vercel.com) 这类无服务器或边缘平台时，这会成为问题。

在无服务器环境中，每个用户请求都会触发一个全新的 Nuxt 服务器实例，每次都从零开始。这种“无状态”特性意味着你无法把数据存在服务器内存中，也无法使用 SQLite 这类基于文件的数据库。因此我们实现了数据库适配器，让数据独立于服务器实例持久化。

::prose-note
我们会根据你在配置中设置的[数据库类型](https://cfec52f9.content-f0q.pages.dev/docs/getting-started/configuration#database)，自动切换到相应的提供商（Vercel / Postgres、NuxtHub / D1……）。
::

### 浏览器中的 WASM SQLite

在客户端导航方面，模块采用了类似的方式。当应用执行第一次内容查询时，它会从服务器下载生成的数据库转储，并在浏览器中初始化一个本地 SQLite 数据库。此后所有查询都在本地执行，无需请求服务器：显著提升了应用响应速度，带来流畅的用户体验。

## 🗄️ 内容集合

集合是 Nuxt Content 项目中一组组相关的内容条目。它们能帮助你更高效地组织和管理大型数据集。

### **定义集合**

现在你可以在 [`content.config.ts`](/docs/getting-started/configuration) 文件中定义集合，用来配置数据库结构、工具类型，以及查找、解析和查询内容的方法。

### **集合模式**

模式保证集合内部的一致性，并改进 TypeScript 类型，从而更好地与 Nuxt Content 的工具集成。

```ts [content.config.ts]
import { defineCollection, z } from '@nuxt/content'

// Export collections
export const collections = {
  // Define collection using `defineCollection` utility
  posts: defineCollection({
    // Specify the type of content in this collection
    type: 'page',
    // Load every file matching this pattern
    source: 'blog/**/*.md',
    // Define custom schema for this collection
    schema: z.object({
      date: z.date(),
      image: z.object({
        src: z.string(),
        alt: z.string()
      }),
      badge: z.object({
        label: z.string(),
        color: z.string()
      })
    })
  }),
}
```

在文档中进一步了解集合。
::

## 🔧 简化的 Vue 工具函数

我们简化了工具函数，现在只暴露以下几个：

- [queryCollection](/docs/utils/query-collection)：用我们强大的查询构建器获取你的集合
- [queryCollectionNavigation](/docs/utils/query-collection-navigation)：获取某个集合生成的导航
- [queryCollectionItemSurroundings](/docs/utils/query-collection-item-surroundings)：获取指定路径的相邻内容
- [queryCollectionSearchSections](/docs/utils/query-collection-search-sections)：从集合中获取可搜索的区块，提升内容可发现性

这四个工具函数让你能在 Vue 页面和组件中高效地获取和查询内容：

```vue [pages/blog.vue]
<script setup lang="ts">
const { data: posts } = await useAsyncData('blog', () => {
  return queryCollection('blog').all()
})
</script>

<template>
  <div>
    <h1>Blog</h1>
    <ul>
      <li v-for="post in posts" :key="post.id">
        <NuxtLink :to="post.path">{{ post.title }}</NuxtLink>
      </li>
    </ul>
  </div>
</template>
```

## 📦 内置组件

我们更新了组件，只保留最核心的几个：

- [ContentRenderer](/docs/components/content-renderer)：把解析后的 Markdown 渲染为 HTML 与 Vue 组件
- [Slot](/docs/components/slot) 取代了 `ContentSlot`，因为我们现在支持通过指令解包，让你的 Vue 组件可以完美地在 Vue 和 Markdown 中通用
- [Prose 组件](/docs/components/prose) 是为 MDC 语法量身定制的预设组件，内置样式，外观出色

下面是一个展示 Markdown 文件内容的例子：

```vue [pages/about.vue]
<script lang="ts" setup>
const { data: page } = await useAsyncData(() => {
  return queryCollection('content').path('/about').first()
})
</script>

<template>
  <ContentRenderer v-if="page" :value="page" />
  <p v-else>About page not written yet.</p>
</template>
```

## 🔷 TypeScript 集成

新的集合系统会为你的所有数据自动提供 TypeScript 类型。每个工具和 API 都基于你的集合定义做强类型化，确保整个开发过程中都有可靠的类型安全。

## 🖼️ Studio 集成

[Nuxt Studio](/studio) 是一个用于在生产环境中可视化编辑你的 **Nuxt Content** 项目的平台。我们的编辑器支持 `Markdown`、`YAML` 和 `JSON` 文件，兼顾灵活性与易用性。

### 预览 API

[Studio 模块](https://github.com/nuxtlabs/studio-module)过去是一个独立模块，现在已更新得更加通用，并作为 `Preview API` 直接集成进 Nuxt Content。

在 Studio 中启用预览功能比以往更容易——只需在 Nuxt Content 配置中把 Studio API 配置为你的 `Preview API`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    preview: {
      api: 'https://api.nuxt.studio'
    }
  }
})
```

这一简化意味着 Studio 不再需要额外的模块，配置更快。此外，Preview API 现在是通用的，其他提供商也能在 Nuxt Content 之上提供出色的编辑体验。

### **统一的文档**

除了这次集成，我们还把 **Content** 与 **Studio** 的文档和网站统一成一个完整的资源。只有 Studio 平台（用户登录后可用）仍保留为[独立站点](https://nuxt.studio)。

**现在我们可以充分利用 Studio 中的数据结构与集合**。Studio 平台支持**集合**与**用户自定义模式**，并会据此调整自身行为。这一增强将为 `YAML` 和 `JSON` 文件以及 Markdown 文件中的 front-matter 提供由模式生成的表单。
